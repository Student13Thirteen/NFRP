# Functional synchronization — 17 August 2026

This release aligns the public NFRP reference implementation with the code-level behavior of the operational transport ERP on 17 August 2026 while preserving a strict public-data boundary.

## Included in this synchronization

- unified customer records for container trips, with VAT number, tax code and certified-email fields;
- supplier fiscal fields and reusable quick-create supplier controls;
- driver employment periods with explicit start, end and end-reason history;
- dated tractor-driver assignments, historical lookup and cross-links between driver and tractor pages;
- OCR trip review that proposes the nearest existing driver name, lets the operator correct it from the registry and creates the trip only after confirmation;
- split allocation of one expense line across multiple vehicles or warehouse targets;
- document types that can be non-expiring, including digital tachograph update evidence;
- reversible toll discard and restore, with discarded rows excluded from cost/report consumers while original-file totals remain transparent;
- duplicate recovery guidance when a discarded toll file is uploaded again;
- transactional and idempotent manual fuel and expense creation;
- form recovery after server-side validation errors, including dynamic rows;
- discoverability improvements: clearer dashboard trip actions, active navigation for the document inbox and an explicit driver-to-vehicle assignment path;
- five additive Prisma migrations and synthetic seed records that exercise the new master-data relationships.

## Public-data boundary

The repository does not contain or derive from production databases, uploaded documents, backups, `.env` files, credentials, private endpoints or operational company records. Personal names, plates, suppliers, fiscal identifiers and OCR samples used in public tests are synthetic.

The operational installation contains provider- and document-layout-specific regression evidence. The public edition keeps equivalent parser behavior with synthetic signatures and fixtures. External integrations such as Nextcloud, Telegram, Ollama and Cloudflare require the operator's own configuration and are not connected to production services by this repository.

Internal AI handoffs, private UX audit artifacts and server-specific deployment notes are not application features and are intentionally not copied into the public project.

## What parity does not mean

This is functional parity for the identified modules and workflows, not a claim that a public clone is the production deployment. It intentionally excludes production content and live integration configuration. The public tour was checked at desktop and mobile sizes, but the complete server application has not received a full route-by-route screenshot matrix or a formal real-operator usability study. The broader UI/UX simplification program remains iterative.
