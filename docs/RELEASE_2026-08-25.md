# Functional synchronization — 25 August 2026

This release moves the public NFRP boundary from 19 to 25 August 2026. The working transport ERP remains the sole functional reference; NFRP receives a sanitized implementation with synthetic identities, providers, fixtures and seed data.

## Included in this synchronization

### Classified and externally owned fleet

- motor vehicles can be classified as tractor units, rigid trucks, cars or pending classification;
- trailers have explicit body types, including container, tank, refrigerated and curtain-sided configurations;
- tank trailers carry a specific cargo classification;
- tractors and trailers can be marked as externally owned and linked to a reusable owner registry;
- fleet documents, fuel entries, container trips and maintenance flows understand the expanded fleet model without merging external assets into company ownership.

### Road fines and road accidents

- separate registers for `Verbali` and `Sinistri stradali`, with separate create/detail workflows;
- explicit state and responsibility, vehicle/driver links, dates, deadlines and monetary fields;
- road accidents may be linked to maintenance costs without turning an unconfirmed maintenance import into an accounting record;
- attachments are stored outside `public/` and served through an authenticated route;
- related events appear in driver and vehicle workspaces, on the dashboard and in the cost center;
- the synthetic seed contains one invented fine and one invented accident so both flows can be inspected immediately.

### Reliable register pagination

- selecting 50, 100, 200 or all rows uses a server-backed navigation and keeps the chosen value stable;
- active filters survive a page-size change;
- applying document and registry filters no longer silently restores the default page size;
- long fuel lists avoid unnecessary link prefetching.

### Version awareness

- the authenticated shell checks the running application build and shows a restrained reload notice when a new build replaces the one open in the browser.

## A real local demo, not a static imitation

The former dependency-free GitHub Pages tour and its deployment workflow were removed. A static page cannot exercise PostgreSQL, authentication, OCR, protected files, migrations or review queues and is therefore not presented as the product.

The public entry point is now:

```bash
git clone https://github.com/Student13Thirteen/NFRP.git
cd NFRP
bash nfrp quickstart
```

`quickstart` is non-interactive, binds only to `127.0.0.1`, creates strong credentials, applies all migrations, loads synthetic demo data and starts no tunnel. It refuses to overwrite an existing installation. The guided `bash nfrp setup` path lets the operator choose the initial administrator email and password, or request an automatically generated password.

Windows uses Docker Desktop with WSL 2, macOS uses Docker Desktop and Linux uses Docker Engine. No server or Cloudflare account is required for local evaluation. This release verified the containerized path on Linux; a physical Windows and macOS acceptance run is still recommended before claiming native-platform certification. NFRP is not yet a signed `.exe` or `.dmg` desktop application.

## Public-data boundary

The repository contains no production database, uploaded document, backup, `.env`, credential, private endpoint, company logo or company record. Provider-specific OCR signatures and regression fixtures use synthetic equivalents. The complete Prisma schema and all 36 additive migrations are present because they are program structure, not company data.

## What parity does not mean

This is behavioral and schema parity for the identified transport workflows, not a byte-for-byte export of a private deployment. Public branding, sample identities, provider names and document signatures intentionally differ. Production infrastructure, operational data and private backup procedures remain outside this repository. No route-by-route screenshot matrix or formal real-operator usability study was produced for this release.
